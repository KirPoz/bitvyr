# Аудиосопроцессор ESP32-C6

C6 обслуживает Bluetooth через Hosted и рассчитывает PCM 48 кГц из пакетов APU,
которые отправляет P4. Каждый запрос привязан к поколению игры, номеру кадра
и транспортной эпохе. Результат передаётся P4 по SDIO для вывода через I2S.

| Папка | Ответственность |
|---|---|
| `src` | Приём запросов, очередь, расчёт PCM, подтверждение передачи и освобождение источника |
| `apu_fixed` | Фиксированная арифметика синтеза и фильтрации PCM |
| `project` | Проект ESP-IDF 6.1, конфигурация Hosted и исходники для SDK |
| `recipe` | Пути и SHA входов, порядок компиляции и линковки |
| `provenance`, `patches` | Происхождение исходников, лицензия и изменения Hosted и APU |

Входной callback Hosted публикует запрос в ограниченном числе слотов.
Вычисляющая задача проверяет границы и обрабатывает слоты по порядку.
Callback завершения передачи освобождает источник после совпадения поколения
и номера запроса. При смене игры P4 ждёт окончания обработки и снимает привязку.

`ServiceReady.cpp` проверяет запись по схеме wire, передаёт её рендереру и
возвращает заимствованный PCM с метками пакета. Этот указатель принадлежит
рендереру. Устаревший диагностический opcode11 и встроенные снятые с игр
данные фильтра удалены; штатный расчёт PCM не использовал этот endpoint.
`ResolvedColourCodec.h` и
`ResolvedColourRun.h` связывают имена заголовков с раскладкой рецепта.
Исходники Hosted со SPDX-заголовками и файлы protobuf закреплены по байтам.

Рецепт содержит39 единиц трансляции:19 собственных и20 сохранённых baseline.
Имя `recipe/compile41.json` оставлено для совместимости ссылок, но оба удалённых
диагностических объекта не входят в компиляцию и архив. Известный установленный
worker f4 и его admission остаются прежними; новый исходный worker требует
собственной проверки и явного ELF SHA в P4.

## Переносимая подготовка сборки

Нужны Windows, Python 3.11+ и ESP-IDF 6.1 с `riscv32-esp-elf 15.2.0_20251204`,
CMake 4.0.3 и Ninja 1.12.1. Текущий ordered-рецепт закрепляет Windows executables
по SHA. Перенос каталогов поддерживается; другая ОС или toolchain требуют
отдельного reviewed recipe. SDK и его binary submodules Bluetooth/PHY/Wi-Fi
устанавливаются отдельно; они перечислены в `recipe/external-lock.json`.

Из папки `betta` исходники проверяются без SDK, ROM, платы и прежнего `build`:

```powershell
python -B coprocessor/c6_audio/tools/build.py --audit
```

В Git хранится только минимальный seed `config/sdkconfig.profile` с 63 явно
проверенными аппаратными и буферными настройками. Вместе с тремя tracked defaults
он задаёт вход Kconfig. Локальный игнорируемый `config/sdkconfig` не читается.
При выполнении плана полный SDK-generated профиль проверяется по logical SHA
после configure и до компиляции. Дрейф означает HOLD, а не незаметную смену режима.

`--prepare` создаёт новый каталог и план, но не запускает SDK:

```powershell
# Активированный терминал ESP-IDF: IDF_PATH, IDF_TOOLS_PATH и SDK Python virtualenv.
python -B coprocessor/c6_audio/tools/build.py --prepare --out build/c6_audio/release
```

Явные параметры: `--idf <SDK> --idf-tools <tools-root> --toolchain <riscv32-esp-elf-root>
--python <venv-python> --cmake <cmake> --ninja <ninja>`. Без аргумента выбирается
только инструмент с совпавшим SHA из окружения/PATH/установки IDF. Неизвестные
байты вызывают отказ; совпадение номера версии недостаточно. Для следующей
попытки выберите новый `--out`. Выход допускается в `betta/build` либо
в выделенном `%TEMP%/bitvyr-c6-audio/<name>`; корневой каталог не используется.

Только отдельная команда исполняет план сборки:

```powershell
python -B coprocessor/c6_audio/tools/build.py --execute-root build/c6_audio/release/plan.json
```

Она не прошивает устройство и не выполняет OTA/COM. Новая сборка получает
собственные ELF/BIN SHA и требует отдельной проверки на плате. Совпадение
исходников не обещает прежний ELF hash: descriptor SDK, пути и другие параметры
сборки могут его изменить. P4 проверяет exact worker ELF и capability при HELLO
и не принимает неизвестный worker автоматически. Для новой пары Root должен
квалифицировать worker и передать его полный ELF SHA через CMake-параметр
`NES_C6_WORKER_SHA256` при сборке P4. Заголовок admission вручную не меняется. При обновлении
только P4 через Flash App сохраняйте совместимый уже установленный worker C6.
